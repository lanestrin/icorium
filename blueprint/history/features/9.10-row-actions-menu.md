# Feature: Row actions menu

**From build-plan:** feature 9.10
**Build attempt:** 1
**Branch:** `feature/9.10-row-actions-menu`
**Status:** verified

## Goal

Make the file table quieter. Replace the **Preview** and download buttons on
each Active Files row with the ⋯ **Actions** menu the Archived tab already
uses. Every row then has one compact control, as in the person's 9.9 mockup.
Presentation only.

## Design reference

[`blueprint/reference/9.9-compact-file-table.png`](../reference/9.9-compact-file-table.png):
a ⋯ button in a centred **Actions** column. The menu's look and behaviour are
the existing Archived `RowMenu`.

## In scope

- **Active Files rows** (`client/src/components/FileTable.tsx`): one ⋯
  trigger per row with the label `Actions for <File ID> <filename>`. Its menu
  holds **Preview file** and **Download file**; the download goes to
  `api.downloadUrl(id)`.
- **Archived rows:** the menu is unchanged: Preview file, Download file and
  Restore file, with Restore disabled while restoring.
- **One menu for both tabs:** `RowMenu` takes `onRestore` as optional and
  shows **Restore file** only when it is given. The Actions header and cell
  are centred in both tabs.
- **Focus return (a fix that also applies to Archived):** choosing **Preview
  file** puts focus back on the row's ⋯ trigger before the preview opens.
  The preview modal remembers that trigger, so closing the preview returns
  focus there. Today focus is lost, because the menu item it would return to
  has been removed.
- **Unchanged:** the menu's keyboard behaviour (Enter/Space opens and focuses
  the first item, arrow keys move, Escape or a click outside closes and
  returns focus to the trigger), selection (opening the menu never toggles
  the row), bulk Archive/Restore/Compare, processing, filters, sorting,
  downloads and the API.

## Out of scope

- **Archive file** in the menu (archiving stays in the selection bar).
- The mockup's card header with a file count.
- Any change to the preview modal or the download endpoint.
