# Feature: Make server settings configurable and name the fixed limits

**From build-plan:** feature 10.12
**Build attempt:** 1
**Branch:** `chore/configurable-server-settings`
**Status:** verified

## Goal

The upload size limit, log level and bind host can be changed through
environment variables without editing code, with today's values as defaults.
The server's startup and failure messages go through the app logger where an app
exists. The remaining fixed limits are named constants listed in one README
section. Behaviour with no variables set is unchanged.

## In scope

1. **Settings from the environment.** `serverSettings(env = process.env)` in
   `server/src/app.ts` returns `{ maxUploadMb, logLevel, host, port }`:
   - `MAX_UPLOAD_MB`: default `DEFAULT_MAX_UPLOAD_MB = 10`. It must be a positive
     number (decimals allowed, e.g. `0.5`); anything else stops startup with
     `MAX_UPLOAD_MB must be a positive number of megabytes, got "<value>".`
   - `LOG_LEVEL`: default `DEFAULT_LOG_LEVEL = 'warn'`. It must be one of
     `fatal`, `error`, `warn`, `info`, `debug`, `trace` or `silent`; otherwise
     startup stops with `LOG_LEVEL must be one of fatal, error, warn, info, debug, trace, silent, got "<value>".`
   - `HOST`: default `0.0.0.0`. `PORT`: default `3001`, read as today.
   - An empty variable counts as unset.
2. **Using them.** `buildApp(logger?, store?, settings = serverSettings())`:
   the logger defaults to `{ level: settings.logLevel }` (tests still pass
   `false`), and multipart's `fileSize` is `settings.maxUploadMb * 1024 * 1024`.
   `index.ts` reads `serverSettings()` once, passes it to `buildApp`, and listens
   on `settings.host` and `settings.port`.
3. **Logging in `index.ts`.** After `listen`, log `API on http://localhost:<port>`
   with `app.log.info`, and log a failed `listen` with `app.log.error`.
   `console.error` stays only for a failure before the app exists (bad settings,
   storage refusal), since there is no app logger yet; the process still exits
   with code 1.
   - At the default `warn` level the `API on …` line no longer prints;
     `LOG_LEVEL=info` shows it, along with Fastify's own "Server listening" line.
     See Open questions.
4. **Named constants, unchanged values**, each with a one-line comment:
   - `PREVIEW_MAX_ROWS = 1000` for the preview page cap (`pageQuery` in
     `server/src/routes/files.ts`).
   - `BLOB_LIST_PAGE = 1000` in `server/src/lib/blob-storage.ts`.
   - `GENERATOR_FIRST_DAY` (2026-09-01) and `GENERATOR_RANGES` (mass 110–140 kg,
     R-32 33–40 %, R-125 26–33 %) in `server/src/lib/generate.ts`.
   - Already named, no change: `TOAST_MS` (`client/src/hooks.ts`),
     `DEMO_CLASS_RULES` (`server/src/processing/index.ts`).
5. **README "Settings" section.** One table of the four environment variables
   (default, meaning, valid values), plus a table naming each constant above
   with its file and value. The existing RECLAIM_*, BLOB_* and VERCEL variables
   stay documented where they are, with one line in the new section pointing to
   them.
6. **Architecture page.** The "capped at 10 MB" sentences stay true as the
   default. Update `architecture-content.test.ts` so it checks
   `DEFAULT_MAX_UPLOAD_MB = 10` and `DEFAULT_LOG_LEVEL = 'warn'` in `app.ts`,
   instead of the old literals.

## Out of scope

- Making the constants in item 4 environment-configurable.
- Client settings, storage behaviour, 10.11.
- Changing any default value or API response.

- New optional environment variables: `MAX_UPLOAD_MB`, `LOG_LEVEL`, `HOST`
  (plus the existing `PORT`). Unset means today's behaviour.
- An invalid value stops startup with a message naming the variable, rather
  than silently falling back.
- No API, stored-data or client change.
