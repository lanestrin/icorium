# Feature: Give each partner adapter its id and formats

**From build-plan:** feature 10.7
**Build attempt:** 1
**Branch:** `refactor/partner-adapter-formats`
**Status:** verified

## Goal

A new partner format (columns, units, number formats and the generator's
description) is one adapter entry, and the CSV generator offers it with no other
edit. Generated files stay byte-for-byte the same.

## In scope

1. **One partner table, in `shared/types.ts`.** The generator page (client) needs
   the partner list and its descriptions, and the client cannot import server
   code, so the adapter entries move from `server/src/adapters/index.ts` to
   `shared/types.ts` as `ADAPTERS`. Each entry:
   `{ id, name, description, columns, massFactor, pctFactor, digits: { mass, pct } }`,
   with today's values:
   - A: `Partner A`, `Kilograms and percentages`, digits mass 3 / pct 2
   - B: `Partner B`, `Pounds and percentages`, digits mass 3 / pct 2
   - C: `Partner C`, `Grams and fractions (0–1)`, digits mass 0 / pct 5
   Columns and factors are unchanged. Declare the list `as const` (with a
   `satisfies` shape check) so ids stay literal types.
2. **Derived partner ids.** `GENERATOR_PARTNERS = ADAPTERS.map((a) => a.id)` and
   `GeneratorPartner` is the union of adapter ids. The Zod partner enum in
   `server/src/routes/files.ts` and its message are built from that list; the
   message text stays exactly `Choose partner A, B or C`.
3. **Server adapters keep the logic.** `server/src/adapters/index.ts` keeps
   `Normalized`, `num` and `getAdapter` (matching, normalizing, the
   "Unrecognized CSV schema" message), reading `ADAPTERS` from shared. Behaviour
   and messages unchanged.
4. **Generator.** `server/src/lib/generate.ts` finds the adapter by `id` and reads
   `adapter.digits`; `DIGITS` and the `Partner ${partner}` lookup are deleted. Keep
   the unknown-partner guard (`Unknown partner X.`) for a direct caller.
5. **Generator page.** `client/src/components/GeneratorPage.tsx` lists `ADAPTERS`
   and shows each entry's `name` and `description`; its local `PARTNERS` table is
   deleted. The visible text stays `Partner A` / `Kilograms and percentages` etc.
6. **Docs.**
   - `CLAUDE.md` "Extending" and README's "New partner CSV schema" line: a new
     partner is one entry in `ADAPTERS` in `shared/types.ts`. Drop the
     `GENERATOR_PARTNERS` and `DIGITS` steps. CLAUDE.md "Layout" line for `server/`
     still describes `src/adapters/` (matching and normalizing).
   - Architecture page (`client/src/components/ArchitecturePage.tsx`): keep "one
     adapter entry" (still true). Fix the adjacent sentence at ~line 251 that 10.6
     left stale: a new calculation no longer needs "the API's allowed values"; it
     is one processor plus its entry in the shared processor list.

## Out of scope

- Changing any partner's columns, units, formats, names or descriptions, the
  generated values or file names.
- Client logic moves (10.8), storage, caching or settings (10.9–10.12).
- Browser tests.

## Notes for the AI

- `shared/types.ts` is imported by the client bundle; the moved entries are plain
  data with no server imports, so this adds nothing server-only to the client.
- Build the message as `Choose partner ${ids.slice(0, -1).join(', ')} or ${ids.at(-1)}`
  so it reads `Choose partner A, B or C` today.
- `generateCsv` uses the partner id for batch IDs (`A-001`) and file names
  (`partnerA-…`); keep using `id`, not `name`.
