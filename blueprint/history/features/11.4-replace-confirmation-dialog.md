# Feature: Replace confirmation dialog

**From build-plan:** feature 11.4
**Build attempt:** 1
**Branch:** `feature/11.4-replace-confirmation-dialog`
**Status:** verified

## Goal

Ask before a re-run replaces a result. Since 11.3 the server refuses an
unconfirmed re-run with 409, and the app just shows that message as the file's
error. After this item, **Run Processing** opens a **Replace existing result?**
dialog listing every result the run would replace (combined with the Data
Quality Warning when that also applies). **Cancel** sends nothing; a red
**Run & Replace** sends `replace: true` for exactly the listed files, once. If the
file list was stale and the server still answers 409, the app shows the same
confirmation for those files instead of reporting an error or retrying silently.

## Design reference

The person's mockup, as recorded in the build plan (11.4): title **Replace
existing result?**, body "Composition Validation has already been run for file
**101010**. Running it again will replace the existing result **101010-V**. This
action cannot be undone.", **Cancel** and a red **Run & Replace**. Visual style
follows the existing `QualityWarningModal` (narrow `Modal`, rounded buttons,
bottom-right actions) and `blueprint/reference-ui.png`.

## In scope

- Before running, the client finds which selected inputs already have a result
  for the chosen function: the result ID `resultFileId(input.id, processor)` is
  in the current file list (Active or Archived).
- One confirmation dialog when any replacement applies, listing each replaced
  result, noting archived ones, and including the Data Quality Warning details
  when that warning also applies. Files without an existing result run normally.
- Run & Replace sends `replace: true` only for the listed files, and nothing for
  the others; once per file even on a double click.
- `api.process` sends `replace` and exposes the server's `ReplaceConflict` on 409.
- A 409 during a run (stale list) is collected, not reported as an error; after the
  batch the same dialog opens for those files.
- README: drop the "until 11.4" note and describe the dialog.

## Data / contracts

- **Request** (unchanged server contract): `POST /api/process`
  `{ fileId, processor, replace? }`; the client sends `replace: true` only for
  files the person confirmed in the dialog.
- **409 body** (from 11.3, `shared/types.ts`): `ReplaceConflict` `{ message,
  existing: { id, name, archived? } }`. The client reads `existing` to build the
  dialog for a stale-list conflict.
- **Result ID rule:** `resultFileId(inputId, processor)` from `shared/types.ts`;
  matching is by full File ID, never by file name.
- **Client state:** the pending dialog holds the batch, the processor, the
  replacement list and an optional quality warning. In memory only; nothing persisted.
- No server, storage or shared-type changes.

## Notes for the AI

- `vi.mock('./api')` in `App.test.tsx` replaces the whole module, so do not put a
  class or helper the App needs at runtime in `api.ts`; detect a conflict in
  `App.tsx` by the `conflict` property.
- Keep `QualityWarningModal` and its tests as they are; share its content block
  rather than duplicating copy.
- Test fixtures use short IDs (`clean`, `invalid`); a result fixture for the
  replacement cases needs the ID `resultFileId(input.id, processor)` (for example
  `clean-V`), since matching is by computed ID.
- Successful files in a batch with conflicts keep today's behaviour (refresh,
  notice or preview). Only the selection keeps failed and conflicted files.
- No new dependency. No em dashes in copy, docs or comments.

## Try it now

1. Run `npm run dev` and open http://localhost:5173.
2. Tick `partner_c_baseline.csv`, choose **Composition Validation** and click **Run Processing**. The result preview opens; close it.
3. Tick the same file again, keep **Composition Validation** and click **Run Processing**: **Replace existing result?** names file `100005` and result `100005-V`.
4. Click **Cancel**: nothing runs and the file stays ticked. Run again and choose **Run & Replace**: the result is replaced and its preview opens.
5. Optional: archive `100005-V` first, then repeat step 3. The dialog says the result is archived; after replacing, it is back in **Active Files**.
