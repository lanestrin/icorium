# Feature: Give both storage backends one async interface

**From build-plan:** feature 10.9
**Build attempt:** 1
**Branch:** `refactor/storage-interface`
**Status:** verified

## Goal

Local and Blob storage implement one declared async `Storage` interface, local
storage never hands out its live objects or blocks on `fs`, an interrupted
metadata write cannot corrupt `meta.json`, and importing the storage module does
nothing until `buildApp` opens storage. API behaviour and stored formats stay
the same.

## In scope

1. **One `Storage` interface** in `server/src/lib/storage.ts`, with today's
   methods, all async: `list`, `get`, `read`, `patch`, `create`, `put`,
   `createAt`, `seed`. `NewFile` and `NewUpload` are defined once there;
   `blob-storage.ts` imports them as types and `createBlobStorage` returns
   `Storage`.
2. **Local storage, opened explicitly.** `openLocalStorage(dataDir)` (async)
   creates `files/`, reads `meta.json` and keeps the File ID check with today's
   message, then returns a `Storage`.
   - Uses `node:fs/promises` only.
   - `list` and `get` return copies (`structuredClone`), so callers cannot change
     stored metadata.
   - `meta.json` is written to `meta.json.tmp` and renamed over `meta.json`.
     Metadata writes run one after another, each writing the latest metadata,
     so an older snapshot never lands last.
   - In-process atomicity is kept: `create`, `createAt` and `put` record the new
     metadata in memory before their first `await`, so two requests at the same
     time still cannot get the same File ID or both create one result. If the
     write then fails, the in-memory change is undone and the error is thrown.
3. **Explicit startup.** The module has no top-level side effects.
   `createStorage(env = process.env)` picks the backend with today's rules
   (Blob when `BLOB_READ_WRITE_TOKEN` is set and `RECLAIM_DATA_DIR` is not;
   refuse to start on Vercel without Blob, same message; local folder from
   `RECLAIM_DATA_DIR` or `server/data`). `buildApp(logger, storage?)` uses the
   given storage or `await createStorage()`, then seeds, reconciles and registers
   `fileRoutes` with `{ storage }`. `seedSamples(storage)` and
   `reconcileMetadata(storage)` take the storage they work on.
4. **No backend checks outside storage.** `seedSamples` drops its
   `!useBlob && fs.existsSync(META)` shortcut and relies on `seed` skipping IDs
   that are taken, which both backends already do. Reading the five sample CSVs
   at each start is the only extra work.
5. **Tests.**
   - `api.test.ts` builds the app with `openLocalStorage(dataDir)` and uses that
     instance directly; no environment variable before import, no
     `vi.resetModules()`. Its restart test opens a second instance on the same
     folder.
   - Blob API tests in `blob-storage.test.ts` keep stubbing the environment but
     no longer need `vi.resetModules()`.
   - A shared contract suite runs against both local (temp folder) and Blob
     (mocked SDK): create numbering, `get`/`list` copies, `put` replace,
     `createAt` refusal, `patch`, `seed` idempotence, 404 for a non-File ID.
   - Atomic write test: with `meta.json.tmp` blocked (a folder in its place), a
     `patch` fails, `meta.json` still parses with the previous content, and a
     fresh `openLocalStorage` on the folder starts.
   - `createStorage({ VERCEL: '1' })` rejects with the existing message.
6. **Included by the person's decision at completion:** their one-line
   `client/src/App.tsx` edit, toast width `sm:w-[26rem]` → `sm:w-104` (the same
   26rem in Tailwind 4). Unrelated to storage; no behaviour change.
7. **Docs.** Architecture page: local storage text says `meta.json` is replaced
   atomically. `architecture-content.test.ts` checks for `meta.json`,
   `BLOB_READ_WRITE_TOKEN` and the Vercel refusal; adjust its regex if the
   expression becomes `env.VERCEL && !useBlob`.

## Out of scope

- Caching parsed rows (10.10), Blob lookup performance (10.11), configurable
  settings (10.12).
- Changing the Blob layout, CSV or `meta.json` formats, File ID rules or any API
  response.

  JSON, 2-space indent); Blob objects `files/<id>.json` and `claims/<base>.json`.
- A leftover `meta.json.tmp` from a crash is ignored at start and overwritten by
  the next write.
- No API change. `index.ts` keeps calling `buildApp()`.
- Only `server/src/lib/storage.ts` (and `blob-storage.ts` for Blob) touch
  storage, as `CLAUDE.md` requires.
