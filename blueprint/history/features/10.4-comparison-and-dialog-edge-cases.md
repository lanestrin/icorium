# Feature: Comparison and dialog edge cases

**From build-plan:** feature 10.4
**Build attempt:** 1
**Branch:** `fix/comparison-and-dialog-edge-cases`
**Status:** verified

## Goal

Close four small correctness gaps found in the 2026-11-10 review:
- comparison row keys that can collide with a real batch ID
- "rows differing" that treats `100` and `100.0` as different
- a generator retry loop with no limit
- a dialog focus trap that counts disabled fields

What people see stays the same, except where the old behaviour was wrong.

## In scope

- **Row keys cannot collide** (`server/src/lib/compare.ts`, `matchRows`).
  `MatchedRow` gets a separate display `label`, while `key` becomes an
  identifier only:
  - Batch-ID matching: key `id:<n>:<batch ID>` for the n-th occurrence of an
    ID, and `blank:<file>:<row>` for a blank ID. The label is unchanged:
    `B-010`, `B-010 (2)`, `(blank ID) file 1 row 3`.
  - Position matching: key and label are both `#<n>`, as now.
  - Rows are matched by key, so a real batch ID `B-010 (2)` and the second
    `B-010` are now separate rows. They share a label, which is accepted: the
    plan keeps the display label.
- **Numeric rows compared by value** (`compareResults`). For a column
  classified numeric, a row differs when any file lacks the row, or when the
  files' values differ as numbers. A blank counts as "no value": blank equals
  blank, and blank differs from a number. So `100` and `100.0` no longer
  differ. Category columns still compare text.
- **Generator retry cap** (`server/src/lib/generate.ts`, `generateFiles`). Stop
  after `GENERATE_MAX_ATTEMPTS = 100` total attempts with
  `httpError(400, "Could not make <count> different files with these
  settings. Try more rows or fewer files.")`. The route already turns this
  into the normal error response and message.
- **Focus trap skips disabled fields** (`client/src/components/Modals.tsx`).
  `FOCUSABLE` becomes `a[href],button:not([disabled]),select:not([disabled]),input:not([disabled]),[tabindex]:not([tabindex="-1"])`.
- **Client shows labels** (`client/src/components/CompareWorkspace.tsx`):
  - `TopDifference` gets `label`.
  - The Top differences row text, the row chart's axis label and the
    row-differences table header cell show `label`.
  - React `key`s stay on `key`.
- **Plan note:** update "What to build next" in `blueprint/build-plan.md`
  (it still names 11.7) to name **10.5** `chore/dead-and-partial-code` next,
  then 10.6 onward.

## Out of scope

- Disambiguating duplicate labels in the display (for example a real
  `B-010 (2)` next to a repeated `B-010`).
- Any other 10.x item. The duplicated `Modal` comment, `detectProcessor`,
  unused exports and the `ERROR` highlight are 10.5; single-sourcing labels
  and limits is 10.6.
- Numeric tolerance. Equal means numerically equal (`Number(a) === Number(b)`),
  not "close".
- Making the attempt cap configurable (10.12 covers configurable settings).

## Data / contracts

- `GET /api/compare` response: each `rows[]` entry gains `label: string`.
  `key` stays a unique string, but its text is no longer meant for display.
  Client and server ship together, so no compatibility layer is needed.
- `rowsDiffering` for numeric columns now counts numeric differences. The
  values and summaries themselves are unchanged.
- `POST /api/generate` can now answer 400 with the cap message. Its other
  responses are unchanged.
- Batch IDs and labels are partner data, rendered as React text only.

## Notes for the AI

- The key prefixes (`id:`, `blank:`, `#`) cannot collide: the parts after
  `id:` and `blank:` are fixed-format, and position keys appear only in
  position mode. The occurrence number sits before the batch ID so that no ID
  text can fake another key.
- Keep the `B-010 (2)` label exactly as it is today; only the key changes.
- Use `Number(v)` on the already-classified numeric cells, as the existing
  code does for `values`.
- `made`/`seed` stay as they are. Removing `seed` from the public API is
  10.5.

  is `fix`; it is still a build-plan feature item, archived under
  `blueprint/history/features/`.
