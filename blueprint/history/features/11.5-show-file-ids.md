# Feature: Show File IDs

**From build-plan:** feature 11.5
**Build attempt:** 1
**Branch:** `feature/11.5-show-file-ids`
**Status:** verified

## Goal

Make every file's File ID visible next to its filename, so people can tell
files apart even when two files have the same name. The File ID becomes a
column of its own in both tabs. Search and sort work on it, and the preview,
the processing panel and the comparison chips show it. Imported result files
are marked so nobody assumes they are linked to an original. Client only: the
API already returns `id` and `imported` on every `FileMeta`.

## Design reference

`blueprint/reference-ui.png` and the existing table styling. File ID is a plain
text column (tabular figures) to the left of **File Name**. The **Imported**
marker is a small neutral pill in the File ID cell, in the same style family as
the status badges. It must still work at phone width: the table already
scrolls inside its own region, so the page itself never scrolls sideways.

## In scope

- **File table (Active and Archived):** a new **File ID** column (`101010`,
  `101010-V`) before **File Name**, which keeps the existing icon and name.
  Processing function and Status columns stay as they are.
- **Imported marker:** files with `imported: true` show an **Imported** pill
  in the File ID cell. Its `title` reads "Uploaded result file. Its original
  input is not linked in this workspace." The preview subtitle says the same
  thing (below), so the explanation does not depend on hovering.
- **Search by ID or filename:** the search box matches when the filename or the
  File ID contains the text, ignoring case. `101010` finds `101010`,
  `101010-V`, `101010-M` and `101010-C`. Label and placeholder become
  "Search file ID or name".
- **Sort by File ID:** two new **Sort by** options in both tabs, **File ID
  (low–high)** and **File ID (high–low)**. Files are ordered by their base
  number in the chosen direction. Within one base, the original always comes
  first, then results in `PROCESSORS` order (`-V`, `-M`, `-C`), whichever
  direction is chosen. The File ID header gets `aria-sort` and the arrow, like
  the other sortable columns. Defaults stay as they are (Uploaded newest /
  Archived newest).
- **Unambiguous row controls:** the row checkbox, download link and archived
  ⋯ menu labels include the ID: `Select 101010 data.csv`,
  `Download 101010 data.csv`, `Actions for 101010 data.csv`.
- **Preview:** the subtitle starts with `File ID 101010-V ·` followed by the
  current text. For an imported file it adds
  `· Imported: original input not linked`.
- **Processing panel (Sidebar):** the selected inputs show both values. With
  one input: `Input: 101010 · data.csv`. With several, each list item reads
  `101010 · data.csv`, and the hover `title` lists them the same way.
- **Comparison:** each file chip shows its short label and then its File ID as
  separate text. The **Reference file** options read `<label> · <File ID>`.
  Every other part of the dashboard already links files to chips by colour dot
  and stays as it is.
- README: update the filter/sort paragraph and the component-test row.

## Out of scope

- **Renaming files.** There is no rename feature (overview Open question
  "Rename has no feature"). The build plan's done-when "renaming changes only
  the displayed filename" cannot be checked yet. This item makes sure the ID is
  shown from `id` alone and never worked out from `name`. Renaming stays with
  whatever item the plan adds later, or with 11.6's decision.
- **Imported lineage semantics.** The current behaviour stays: a new base ID
  plus its function code, `imported: true`, no link to an original. 11.6
  records the decision. This item only displays the existing flag.
- Any server, storage or API change. Showing IDs in the Replace / Data Quality
  dialogs (they already name IDs), the comparison summary table, charts and
  row-difference tables.
- The P2 refactors (10.6 moving `FUNCTION_LABEL`, 10.5 renaming
  `archiveTargets`).

## Data / contracts

No contract changes. The client reads only the existing `FileMeta.id`,
`FileMeta.imported` and `CompareFile.id`. File IDs come from the server
(`^\d{6}$` or `^\d{6}-[VMC]$`) and are rendered as React text. Filenames are
user-controlled text and also stay plain React text, never HTML. `SortKey`
lives only in client state; nothing persists it.

## Try it now

1. Run `npm run dev` and open http://localhost:5173.
2. The file list now has a **File ID** column left of **File Name**: the five samples show `100001` (`partner_a_baseline.csv`) to `100005` (`partner_c_baseline.csv`).
3. Tick `partner_c_baseline.csv`, choose **Composition Validation** and click **Run Processing**; close the preview. The new row shows File ID `100005-V`.
4. Type `100005` in **Search file ID or name**: only `100005` and `100005-V` remain. Clear the filters, then choose **Sort by** > **File ID (low–high)**: `100005-V` sits directly under `100005`.

This proves the File ID column, search by ID and the grouped File ID sort. It is a demonstration, not verification.
